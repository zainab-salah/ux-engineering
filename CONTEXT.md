# Canonical terms

- **Contract evidence:** observed request/response, schema, serializer, validation and permission behavior; not a database type alone.
- **Interaction decision:** a control or workflow chosen for a user's task with a reason, trade-off and contract invariant.
- **Design mode:** establish the user task and contract, choose the interaction, then implement when asked.
- **Audit mode:** inspect an existing implementation, report task-impacting issues with evidence, and fix when requested.
- **Design-system continuity:** preserve established shared components, layout, tokens and state language across screens.
- **Automated validation:** deterministic package/fixture/harness checks; it does not measure usability.
- **Judged evaluation:** a rubric applied to an agent's observable output, with evidence. It is not user research or an automated accessibility test.
- **Baseline:** an independent agent given the same prompt/artifacts without this skill; not deliberately weakened.
- **Severity:** S0 critical, S1 major, S2 moderate, S3 minor, judged by consequences rather than visual preference.
- **History-derived case:** a sanitized synthesis with provenance and explicit retrieval limits. Synthetic fixtures are newly authored, not conversation transcripts.

No tracker is configured for this standalone package. No tracker items were created. This vocabulary resolves the brief's ambiguity between UI styling, UX reasoning, API correctness and validation results; no new architecture trade-off warrants an ADR at this stage.

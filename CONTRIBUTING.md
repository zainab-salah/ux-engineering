# Contributing

Start with a concrete user task, observed failure and relevant contract. Propose the smallest change to a decision rule or reference; do not add a universal rule to fix one personal preference. Preserve scope, permissions, backend behavior and progressive disclosure.

Use synthetic fixtures. Do not contribute customer records, credentials, private screenshots or raw work conversations. Cite external sources and identify what was actually inspected. Distinguish personal preference from a task-impacting defect.

Run the README checks. For behavioral changes, add a realistic scenario or refine an existing one and run an independent baseline/treatment pair when possible. Keep expected criteria separate from runner prompts. Include failures, evidence and untested behavior. Do not replace honest results with fabricated benchmarks.

The package's MIT license applies to original project material; respect licenses and attribution before incorporating third-party content.
